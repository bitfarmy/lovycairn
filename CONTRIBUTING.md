# Contributing

Thanks for helping. Bug reports, translations, documentation and code are all welcome.

## Reporting a bug

Run `lovycairn-doctor --report` and paste its output in the issue: it contains the versions and the relevant lines of the
shell log. If GNOME changed and a feature switched itself off, the notification's **Copy details** button gives the same
information.

## Development setup

You need `gnome-shell` (the real one, to run the tests), `gettext`, `glib2` tools, `desktop-file-utils`, `git` and Node.js.

```bash
scripts/dev.sh check     # syntax, schema, translations, desktop file
scripts/dev.sh test      # smoke test in an isolated headless GNOME Shell (your session is not touched)
scripts/dev.sh pack      # dist/lovycairn@bitfarmy.github.io.shell-extension.zip
tests/run-headless.sh demo tests/out    # more scenes: smoke | demo | hero | compat | frames
scripts/make-screenshots.sh             # regenerate docs/img from clean demo data
```

The tests run a private GNOME Shell with its own D-Bus session, HOME and settings (keyfile backend), so they never read
or write your real files. The demo data (git repositories, launchers, notes) is generated by `tests/fixtures.sh`.

To try your changes in your real session: `scripts/install.sh`, then log out and in (GNOME does not reload extension code).

## Guidelines

- **Keep it reversible and quiet.** No network access, nothing downloaded or executed from outside, nothing changed in the
  user's system without being asked. This is also what extensions.gnome.org requires.
- **Clean up in `disable()`.** Every signal, timer, actor and patched prototype must be undone.
- **Isolate shell internals.** Anything that touches an underscore-prefixed part of GNOME Shell gets a probe in
  `extension/compat.js`, so a GNOME change turns off one feature instead of breaking the extension.
- **Strings:** wrap user-visible text in `_()` (or `N_()` for module-level tables) and add plural forms with `ngettext()`.
  Run `scripts/dev.sh pot` afterwards.
- **Style:** match the surrounding code (4 spaces, single quotes, no semicolon-less lines).
- Each source file starts with the SPDX license header.

## Translations

Copy `po/lovycairn.pot` to `po/<lang>.po` (extension) and `notes/po/lovycairn-notes.pot` to `notes/po/<lang>.po`
(notes app), translate, run `scripts/dev.sh check`, and open a pull request. `tests/run-headless.sh demo` with
`LOVYCAIRN_LANG=<lang>` shows the result.

## Releases

1. Update `version-name` (and `version`) in `extension/metadata.json` and `CHANGELOG.md`.
2. `scripts/dev.sh check && scripts/dev.sh pack`.
3. Tag `vX.Y.Z` and publish a release with the zip from `dist/`.
